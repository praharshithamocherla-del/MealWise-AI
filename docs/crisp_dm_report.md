
# MealWise AI — CRISP-DM Project Report

> **Data integrity notice:** The bundled CSV is synthetic demonstration data. Replace it with approved, anonymized cafeteria records before drawing real-world conclusions. Do not claim measured food-waste reduction from this demo.

## 1. Abstract
MealWise AI demonstrates a machine-learning workflow for estimating breakfast, lunch, and dinner attendance and translating predictions into transparent preparation recommendations. It uses Python, Pandas, scikit-learn, and Streamlit. The initial dataset is synthetic so the pipeline can be tested without representing invented records as real.

## 2. Introduction
Cafeterias need to balance sufficient food availability against unnecessary preparation. Forecasting attendance can support planning, provided that predictions are validated against real local records.

## 3. Problem Statement
Manual estimates may not consistently account for meal type, weekday, menu category, and holidays. MealWise AI explores whether these features help estimate attendance.

## 4. Objectives
- Validate and explore meal attendance data.
- Prepare reusable features.
- Compare a baseline and three regression models.
- Evaluate with MAE, RMSE, and R² on a chronological holdout.
- Show predictions and transparent preparation quantities in a Streamlit interface.

## 5. Existing-System Limitations
Manual planning may be inconsistent and difficult to evaluate systematically. The project does not assume every cafeteria currently uses the same process.

## 6. Proposed System
A modular pipeline validates records, extracts date features, trains models, saves the selected pipeline, and exposes predictions and data exploration in a dashboard.

## 7. System Architecture
CSV records → validation → feature preparation → chronological train/test split → model comparison → saved model + metrics → Streamlit dashboard → demand estimate + preparation recommendation.

## 8. CRISP-DM Methodology
1. **Business Understanding:** reduce planning uncertainty and avoid unnecessary preparation without causing shortages.
2. **Data Understanding:** inspect records, columns, missing values, duplicates, attendance patterns, and provenance.
3. **Data Preparation:** validate types, extract weekday/month/weekend, encode categories, and split chronologically.
4. **Modeling:** compare DummyRegressor, Linear Regression, Decision Tree, and Random Forest.
5. **Evaluation:** compare MAE, RMSE, and R² on the same held-out future period; inspect plots and baseline performance.
6. **Deployment:** serve the saved pipeline through Streamlit.

## 9. Dataset Description and Provenance
`data/synthetic/meal_attendance_synthetic.csv` is generated by this project with a fixed seed. It includes date, meal type, menu category, attendance, and holiday indicator. Its values are artificial, created to test code and demonstrate methodology. No public real-world dataset is claimed.

## 10. Data Preprocessing
The pipeline checks required columns, parses dates, validates meal categories and attendance, and derives calendar features. One-hot encoding is applied to categorical features inside a scikit-learn pipeline. No future attendance value is used as a prediction feature.

## 11. Algorithms
- DummyRegressor: baseline.
- Linear Regression: linear relationship model.
- Decision Tree Regressor: rule-based nonlinear model.
- Random Forest Regressor: ensemble of trees.

## 12. Experimental Setup
The records are sorted by date; the earliest 80% are used for training and the latest 20% for final test evaluation. The random seed for tree-based models is fixed. Synthetic data results are only software demonstration results.

## 13. Evaluation Metrics
- **MAE:** average absolute prediction error in students; lower is better.
- **RMSE:** gives larger errors extra weight; lower is better.
- **R²:** compares the model with predicting the target mean; it may be negative.

## 16. Limitations
Synthetic patterns do not establish real-world accuracy. Inputs omit many potentially important drivers, such as bookings, weather, exams, special events, and sudden schedule changes. Food waste requires measured leftovers data, not attendance predictions alone.

## 17. Future Enhancements
Use permissioned anonymized attendance and leftovers records, add booking/weather/event features when available at prediction time, monitor drift, compare against simple operational rules, and gather cafeteria-manager feedback.

## 18. Conclusion
MealWise AI provides an explainable prototype for meal attendance prediction and planning. Real operational use requires genuine historical records and prospective evaluation.
